## 下一批：真机与正式发布准备

### R01 · 真机、低版本及系统文件选择器验收（P1）

- **目标：** Android7.0 及常用厂商设备完成课程、成绩、导入导出和重启恢复。
- **依据：** 当前主要验证 API36 模拟器和 widget/领域测试，不能代表所有实体设备。
- **步骤：** 备份现有测试数据 → 在 API24 与较新系统各安装一次 → 按 RUNBOOK 跑核心流程 → 重点检查系统文件选择器、键盘、字体缩放、冷启动与升级 → 有缺陷再定位和加回归。
- **依赖：** 可用测试设备、当前 APK；不接入生产校园服务。
- **验收：** 设备型号/系统/步骤有记录，备份可重新导入，force-stop 后数据仍在，无崩溃或明显溢出。
- **风险：** 厂商文件管理器、旧 WebView/系统行为差异；签名变更可能阻止覆盖安装。

### R02 · 发布包名与签名（P1）

- **目标：** 提供可持续升级、可分发的正式 APK。
- **依据：** 当前 com.example.atori、开发签名。
- **步骤：** 确认永久 applicationId 和渠道 → 在安全位置生成/保管发布密钥 → 用本地或 CI 机密注入签名参数 → 校验 release manifest、权限和签名 → 安装/更新验证 → 准备回退与说明。
- **依赖：** 包名与分发方式决定、R01。
- **验收：** APK 用指定发布证书签名，密钥不入源码/备份，后续版本可覆盖更新，版本号和隐私说明准确。
- **风险：** 更改包名会成为另一应用；更换签名不能直接覆盖既有开发包；先做业务备份。

### R03 · 版本管理与构建复现（P2）

- **目标：** 开发者可从确定源码与工具链复现 APK。
- **依据：** 当前已有main分支、pubspec.lock和工具链版本记录，CI与固定工具链自动化仍待完善。
- **步骤：** 检查忽略项 → 初始化 Git 并记录已验收基线 → 固定 Flutter 版本及 SDK组件 → 配置 CI 分析/测试/构建 → 保存校验值和产物记录。
- **依赖：** 已交付源码；CI 账号/运行环境如需外部接入另行配置。
- **验收：** 不跟踪缓存、私有数据、签名或密钥；干净检出可以执行既定检查和构建；产物可追溯。
- **风险：** stable 新版可能提高 minSdk；依赖升级须验证，不能仅修改版本号。

## 真实服务阶段

### S01 · 核实 GPA 与学校作息（P1）

- **目标：** 用户明确选择并使用有依据的学校计算策略。
- **依据：** 当前为标明“非官方”的示例4.0算法；节次为通用默认值。
- **步骤：** 获取权威规则及适用学年 → 明确重修/缓考/非百分制/排除课程口径 → 新增 GpaStrategy 而不修改现有计算器接口 → 添加策略选择 → 用官方例题回归；作息作为可选预设，不覆盖用户配置。
- **依赖：** 官方规则与可验证样例。
- **验收：** 名称、来源与适用范围可见；旧设置/备份兼容；示例策略仍可用；边界计算正确。
- **风险：** 不同学院/年级规则可能不同；策略变化影响展示结果，需保留选择。

### S02 · 接口与登录基础（P1）

- **目标：** 有明确授权的服务能安全登录、退出和失效恢复。
- **依据：** 当前仅有未启用的 HTTPS ApiClient / AuthInterceptor，真实接口和凭据未知。
- **步骤：** 确认接口和授权条件 → 定义请求/响应契约与测试环境 → 加隐私说明与用户选择 → 实现 RemoteDataSource 和鉴权仓库 → 完善统一错误、必要的 CookieManager、凭据读取失败处理 → 凭据写安全存储 → 退出清除凭据且不误删个人本地数据。
- **依赖：** 接口资料、测试账号、隐私约定；发布密钥按渠道需要配置。
- **验收：** 正常/过期/断网/拒绝授权均可恢复；密码、Token、Cookie 不进日志、普通数据库或导出；UI 不直接 HTTP；证书校验不被关闭。
- **风险：** 服务限流、验证码、多因素认证、接口变更；不绕过服务限制。

### S03 · 教务课表与成绩同步（P1）

- **目标：** 授权后导入真实课程和成绩，同时保护手工记录。
- **依据：** 需求第二阶段；当前 TimetableImporter 与本地模型已可用。
- **步骤：** S02 后实现 SchoolImporter/成绩 RemoteDataSource → 映射校历、节次、成绩类型 → 用稳定 sourceId 区分来源 → 提供冲突预览与合并策略 → 原子写入 → 增加迁移与同步测试。
- **依赖：** S01、S02、明确的同步/覆盖业务规则。
- **验收：** 重复同步不重复插入；失败保留原数据；用户可预览并取消；手工数据按约定保留。
- **接口与兼容：** 新来源字段可选，先定义备份迁移策略；必要时 version2 且支持读取 version1。
- **风险：** 非百分制成绩、调课/停课/例外周、来源 ID 不稳定。

### S04 · 第二课堂与志愿真实服务（P2）

- **目标：** 用真实授权活动替换示例展示，用户能分辨数据来源。
- **依据：** 当前共享展示层和 Mock，未提供真实报名。
- **步骤：** 确认两个服务分别使用的接口/身份 → 每个模块 RemoteDataSource → 来源与更新时间标识 → 活动状态映射、缓存和刷新 → 如已授权报名则增加确认、幂等与失败恢复。
- **依赖：** S02、活动与报名契约。
- **验收：** loading/success/empty/error 有设备测试；统计只计已完成记录；示例不冒充真实；报名操作有实际服务结果。
- **风险：** 两个服务认证与时长审核口径不同；报名属于外部写入，需明确用户操作。

考试、提醒、桌面组件等按需求第二阶段另拆任务；校园卡、校园网、电费等不在当前 MVP 中提前加入。
